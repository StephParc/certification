## Description:

Dans cette partie, il s'agit de prendre en compte l'historisation de données. Tout comme pour E5, elle est traitée avec Dbt.  
Les scripts dans le dossier E6 simulent une base OLTP et une évolution du profil client dont on veut garder la trace.  
Le dossier snapshots contient les tables dont on veut surveiller les changements avec les colonnes à observer. Dbt crée automatiquement les colonnes dbt_scd_id (slowly changing dimension), dbt_updates_at, dbt_valid_from et dbt_valid_to.  

Le dossier seeds, quant à lui, permet de stocker des données peu évolutives voire statiques par le biais de fichiers csv. Ils sont convertis en table par la commande `dbt seed`, à exécuter avant `dbt run`. Deux fichiers pour ce projet: les pays pris en compte (nom, fuseau horaire, devise) et les devises (nom, code, symbole). 

Le schéma raw ainsi que les tables, les rôles et les droits sont crées par le script *setup_musicshop.sql*, exécuté par *setup_infra.sh*.  Une policy de sécurité au niveau des lignes (RLS) est ajoutée pour *gold.fact_orders* et *gold.view_fact_orders*, ne rendant visibles aux éditeurs que les commandes les concernant.  

## Orchestration:

Les DAGs concernés sont:  
- *daily_exchange_rates_dag.py* : génération des taux de change quotidien -> sauvegarde dans le data lake -> stockage en base
- *simulate_musicshop_customers_dag.py* : génération de clients -> sauvegarde dans le data lake -> stockage en base  
- *simulate_musicshop_orders_dag.py* : génération de commandes -> sauvegarde dans le data lake -> stockage en base -> modification du profil de certains clients
- *daily_musicshop_update_dag.py* : exécution du pipeline Dbt quotidien (alimentation des tables seeds et des schémas staging, silver, snapshots et gold)

Pour assurer la maintenance, deux DAGs supplémentaires:  
- *test_alerting.py* : tâche destinée à échouer pour tester l'alerting (mail et messagerie) mis en place dans les DAGs  
- *sauvegarde_bases_dag.py* : prend seulement en compte les BDD de E4 à l'heure actuelle mais peut être étendu aux DWH E5 et E6.  Les deux copies les plus récentes sont conservées localement et l'ensemble des copies l'est sur le data lake.  

Selon ce qui est défini dans les DAGs, les alertes sont dans le service de messagerie et/ou par mail à l'adresse indiquée. Pour ce projet, Mailhog simule cette boîte mail visible à l'adresse https://DOMAIN_A_REMPLACER.ngrok-free.dev/mail .
