    Partie E7: Mise en conditions opérationnelles d'un datalake

    Structure de la partie

    
.
├── config/
|   └── access_controle.json
├── E7/
|   ├── __ini__.py
|   ├── benchmark.odp
|   ├── E7.odt
|   └── harvester.py
├── utils/
|   └── S3_utils.py
├── app_catalog.py
└── data_catalog.json

    Description:

    Cette partie du projet concerne la mise en place d'un data lake (Garage dans le cas présent) et du catalogue de données. Les attendus sont dans E7.odt. Toute l'infrastructure est réalisée par le setup_infra.sh. Qui comprend:
    - la génération de la clé hexadécimale pour la configuration garage.toml - démarrage du service et configuration du noeud - assignation d'une capacité (indispensable sinon c'est une coquille vide dans laquelle on ne peut rien stocker)
    garage layout assign --capacity 10G --zone zone-france - application de ce plan garage layout apply --version 1 (v1 pour la création la première fois) - création de clés garage key create <nom de la clé> (récupération de l'id et du secret à ce moment-là) - création de buckets garage bucket create <nom du bucket> - assignation des droits de la clé au bucket garage bucket allow <nom du bucket> --read --write --owner --key <nom de la clé> (droits à adapter selon usage)
    Les commandes dans docker sont bien sûr à précéder de docker exec /garage ... (reste de la commande)

    Il est possible de réaliser les copies, suppressions, déplacements selon les droits accordés à la clé utilisée dans l'utilitaire mais pour les scripts, des fonctions de communication avec le data lake sont définies dans S3_utils.py. Les différents accès sont répertoriés dans access_control.json.

    Le second point important est le catalogue. Il est réalisé avec Streamlit via app_catalog.py. Le module de connexion ne prévoit pour le moment que deux rôles (username: admin et user) avec les mots de passe déclarés dans le .env mais il est possible de constituer un dictionnaire avec les utilisateurs/mot de passe.
    Les métadonnées sont collectées par harvester.py à la fois pour les bases de données et le data lake, et stockées dans data_catalog.json. Elles sont restituées par des onglets: Bases Relationnelles, Data Lake, NoSQL MongoDB, Lignage (sous onglets Transformation, Ingestion, Orchestration) et Santé. L'affichage est adapté au rôle Admin ou User.
    Une barre de recherche permet de filtrer.

    DAG:

    Le catalog est mis à jour quotidiennement par:
    - catalog_dag.py : collecte métadonnées -> stockage -> affichage

    Il peut bien sûr être mis à jour manuellement.

    Exposition:

    L'exposition se fait à l'adresse https://DOMAIN_A_REMPLACER.ngrok-free.dev/ ou http://localhost:8501/ si avez choisi de rester en local.
